# پنل آیکو

اپلیکیشن مدیریتی یکپارچه آیکو کازمتیکس: **فروشگاه و حسابداری**، **قیمت رقبا** و **استودیو محتوا** در یک برنامه، با یک ورود، یک ظاهر (تک‌رنگ و آرام، فارسی و راست‌به‌چپ، روشن/تیره، قابل نصب روی گوشی)، یک صفحه تنظیمات و یک استقرار.

| بخش | از کجا آمد | چه می‌کند |
|---|---|---|
| خانه | جدید | کارهای سریع، چهار عدد اصلی، فهرست «نیاز به توجه» از همه بخش‌ها، آخرین رویدادها |
| فروشگاه و حسابداری (`erp`) | `../ERP` | انبار مرجع، ثبت سریع فروش و خرید کالا، هزینه، حساب شرکا، صورت‌های مالی (ترازنامه، سود و زیان، جریان نقدی)، همگام‌سازی موجودی با سایت (پنل مرجع) |
| قیمت رقبا (`pricing`) | `../Price-checker` | مقایسه با دیجی‌کالا، ترب، باسلام و…، تأیید تطبیق‌ها، قیمت‌گذاری محصول جدید |
| استودیو محتوا (`media`) | `../media-studio-dev` (بازنویسی از Node به Python) | ساخت ویدیو و تصویر با OpenRouter، مقایسه تا ۳ مدل، کتابخانه مشترک تیم |
| تنظیمات | جدید | **همه** تنظیمات در یک جا (هیچ بخشی صفحه تنظیمات جدا ندارد): راه‌اندازی، تیم و دسترسی‌ها (هر نفر یک ورود، نقش جدا در هر بخش)، اتصال‌ها (ووکامرس، پروکسی، OpenRouter)، ربات بله/تلگرام، رسیدها در گوگل درایو، تنظیمات فروشگاه، زمان‌بندی قیمت رقبا، سقف هزینه استودیو، پشتیبان و وضعیت سیستم |

معماری و دلایل انتخاب‌ها: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## ظاهر

یک سیستم طراحی برای همه بخش‌ها (`app/core/web/css/ui.css`): صفحه خاکستری روشن، کارت‌های سفید با خط نازک، مشکی فقط برای چیزی که در هر صفحه مهم‌تر است (زبانه فعال، دکمه اصلی، عدد اصلی) و رنگ فقط برای وضعیت (درست / هشدار / خطا).

* **نوار بالا**: لوگو، بخش‌ها (خانه، فروشگاه، قیمت رقبا، استودیو)، اعلان‌ها و منوی حساب.
* **داک ابزار** (لبه صفحه): جستجو و رفتن به هر صفحه (⌘K)، رویدادها، تیم، تنظیمات، روشن/تیره (با باز شدن دایره‌ای از همان دکمه).
* **زیر عنوان هر صفحه**: صفحه‌های همان بخش به شکل زبانه.
* **گوشی**: بخش‌ها در نوار پایین با دکمه اصلی همان بخش (مثلاً ثبت فروش) در وسط؛ بقیه در منوی حساب.

## اجرا روی کامپیوتر خودتان

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
cp .env.example .env                    # برای توسعه همین کافی است
.venv/bin/python -m app serve           # http://127.0.0.1:8020
```

ورود اول: `amir` یا `tina` با رمز `INITIAL_PASSWORD` (در `.env`). بعد از ورود از «حساب من» رمز را عوض کنید.

برای کار با داده واقعی، از «تنظیمات ← پشتیبان ← دانلود» پایگاه‌داده‌ها را بگیرید و جای پوشه `data` بگذارید — **قبلش کلیدها را پاک کنید** (ووکامرس، ربات، درایو، پروکسی) وگرنه نسخه روی کامپیوتر شما هم با سایت و ربات واقعی کار می‌کند.

دستورهای دیگر:

```bash
python -m app migrate                       # به‌روزرسانی طرح همه پایگاه‌داده‌ها
python -m app set-password amir NEWPASS     # بازیابی رمز
python -m app backup [DIR]                  # پشتیبان همین الان
python -m app pricing crawl [site ...]      # بروزرسانی قیمت از خط فرمان
```

تست‌ها: `.venv/bin/python -m pytest -q`

## استقرار روی سرور (همان سرور ایران فعلی)

> ⚠️ سرور باید IP ایران داشته باشد (سایت آیکو، بلاران و بلا به IP خارج جواب نمی‌دهند و ترب IP دیتاسنتر خارجی را می‌بندد). برای سرویس‌های فیلترشده (تلگرام، OpenRouter) در «تنظیمات ← اتصال‌ها» یک پروکسی خروجی بگذارید؛ همه ارتباط‌های خارجی از آن می‌روند و سایت خودمان، بله و رقبا مستقیم خوانده می‌شوند.

### بار اول

1. یک دامنه (پیش‌فرض در فایل‌ها `aiko.infinitcode.ir`) را به IP سرور وصل کنید.
2. کد را روی سرور ببرید (مثلاً با `scp` یک `git archive`) و در پوشه‌اش:
   ```bash
   sudo bash deploy/bootstrap-server.sh
   ```
   این اسکریپت کاربر سیستمی `aiko`، پوشه `/opt/aiko-panel`، محیط پایتون، `.env` (با یک رمز اولیه تصادفی)، پایگاه‌داده‌ها و سرویس‌های systemd را می‌سازد.
   برای انتقال پنل موجود به سرور تازه، قبل از اجرا فایل‌های `*.db` آخرین پشتیبان را در `/opt/aiko-panel/data/` بگذارید.
3. در `/opt/aiko-panel/.env` مقدار `PUBLIC_URL` و `COOKIE_SECURE=1` را بگذارید و `systemctl restart aiko-panel`.
4. بلوک `deploy/Caddyfile` را به `/etc/caddy/Caddyfile` اضافه و `systemctl reload caddy`.

### استقرار خودکار (CI/CD)

مثل برنامه قیمت فعلی، ولی با تست قبل از ارسال و بازگشت داده:

* هر push به `main` که در پیام یکی از کامیت‌ها `#deploy` باشد (یا «Run workflow» در Actions) → تست‌ها اجرا می‌شوند → بسته با امضای HMAC به `https://<دامنه>/__deploy` فرستاده می‌شود (SSH از بیرون لازم نیست و سرور به GitHub نیازی ندارد).
* روی سرور `deploy/deploy.sh`: عکس از همه پایگاه‌داده‌ها ← جایگزینی کد ← نصب وابستگی‌ها ← مهاجرت ← ری‌استارت ← بررسی `/healthz` ← اگر مشکل بود، کد قبلی **و داده قبلی** برمی‌گردد.
* در GitHub: secret به نام `DEPLOY_SECRET` (مقدار داخل `/etc/aiko-panel/deploy.env`) و variable به نام `DEPLOY_URL`.
* `.env` و `data/` (فقط پوشه‌های سطح اول؛ پوشه‌های هم‌نام داخل برنامه مثل `app/.../counts` جزو کدند) هرگز توسط استقرار دست نمی‌خورند.

### با Docker (جایگزین)

```bash
cp .env.example .env && docker compose up -d --build     # 127.0.0.1:8020
```

## نگهداری

* **موجودی سایت** («فروشگاه ← همگام‌سازی سایت»): پنل مرجع موجودی است و سایت همیشه همان عدد را نشان می‌دهد؛ سفارش‌های سایت خودکار کم می‌شوند و محصول تازه/نام/قیمت از سایت می‌آید. شمارش کامل انبار به‌صورت فایل `app/modules/erp/counts/stock_count_*.json` همراه کد می‌آید و یک بار اعمال می‌شود. جزئیات: [ARCHITECTURE.md](docs/ARCHITECTURE.md).
* **قیمت رقبا**: زمان‌بندی بروزرسانی خودکار در «تنظیمات ← قیمت رقبا»؛ اجرایی که با استقرار/ری‌استارت نیمه‌کاره بماند خودکار از نو اجرا می‌شود.
* **رسیدها در گوگل درایو** («تنظیمات ← رسیدها در گوگل درایو»): رسید هر خرید، فروش و هزینه و فاکتور PDF هر سفارش سایت، مرتب در پوشه سال/ماه/نوع؛ عکس‌ها خودکار کوچک می‌شوند و سقف فضا (پیش‌فرض ۲ گیگ) قابل تنظیم است.
* **وارد کردن تاریخچه سایت** («فروشگاه ← همگام‌سازی سایت ← پیشرفته»، یک بار؛ هر شب سفارش‌های دو هفته اخیر دوباره بررسی می‌شوند): همه محصولات/رنگ‌ها و همه سفارش‌های سایت از اول با مبلغ دقیق (کد تخفیف، ارسال، کارمزد، برگشت وجه). فروش سایتی که دستی یا از اکسل ثبت شده با سفارش سایت جایگزین می‌شود و قیمت خرید اکسل می‌ماند؛ فروش‌های بیرون از سایت، خریدها و هزینه‌ها دست نمی‌خورند. قبل از هر بار، عکس پایگاه‌داده در `data/backups/presync-*`.
* **پشتیبان در تلگرام**: «تنظیمات ← پشتیبان»: ربات را مدیر یک کانال خصوصی کنید؛ هر ساعت یک zip از همه پایگاه‌داده‌ها (از طریق پروکسی) فرستاده می‌شود. فایل بزرگ‌تر از ۴۵ مگابایت چندتکه می‌شود (`cat x.zip.0* > x.zip`).
* **پشتیبان**: هر شب ۳:۱۵ در `data/backups/YYYY-MM-DD/` (یک فایل برای هر بخش + آرشیو رسیدها و فایل‌های استودیو)، ۳۰ روز نگه داشته می‌شود. از «تنظیمات ← سیستم و پشتیبان» هم می‌توانید همه پایگاه‌داده‌ها را دانلود کنید. هر چند وقت یک بار یک نسخه بیرون از سرور نگه دارید.
* **بازگردانی**: سرویس را متوقف کنید، فایل `*.db` مربوط را از پوشه پشتیبان جای فایل `data/` بگذارید (فایل‌های `-wal` و `-shm` همان نام را پاک کنید)، سرویس را روشن کنید.
* **لاگ‌ها**: `journalctl -u aiko-panel -f`
* **حافظه**: سرویس سقف حافظه دارد (۷۵٪ رم)؛ اگر برنامه از آن بیشتر شود فقط خودش ری‌استارت می‌شود و سرور هنگ نمی‌کند. استقرار اگر swap نباشد یک swap دو گیگی می‌سازد. بررسی کمبود رم بعد از هنگ: `journalctl -k -b -1 | grep -iE "out of memory|killed process"`

## ساختار کد

```
app/
  main.py               ساخت برنامه: core + ماژول‌های فعال، پوسته، CSP
  __main__.py           دستورهای خط فرمان
  core/                 هسته مشترک
    auth.py             ورود، نشست، نقش هر ماژول
    db.py               پایگاه‌داده هر ماژول + مهاجرت‌ها
    events.py           رویدادهای زنده (SSE) و هوک‌های بین ماژول
    activity.py         فید یکپارچه، زنگوله، ربات بله/تلگرام
    jobs.py             زمان‌بندی و کارهای پس‌زمینه
    backup.py           پشتیبان‌گیری
    drive.py            رسیدها در گوگل درایو (صف، پوشه‌ها، سقف حجم)
    router.py           API هسته (ورود، تیم، خانه، رویدادها، تنظیمات، فایل‌ها)
    web/                پوسته و کیت مشترک فرانت‌اند (ui.css، app.js، kit.js، صفحه‌های هسته و تنظیمات)
  modules/
    erp/                فروشگاه و حسابداری (+ web/ صفحه‌ها)
      site/             اتصال سایت: client، orders، matching، stock، history
      receipts.py       رسیدها و فاکتور سفارش‌های سایت ← درایو
      statements.py     صورت‌های مالی: ترازنامه، سود و زیان، جریان نقدی
    pricing/            قیمت رقبا (+ sources/ خزنده‌ها، web/)
    media/              استودیو محتوا (+ web/)
deploy/                 systemd، Caddy، دریافت‌کننده استقرار، اسکریپت‌ها
tests/                  تست‌ها (pytest)
```

آیکون‌ها از [Lucide](https://lucide.dev) (ISC)، فونت وزیرمتن، نمودارها با Chart.js.
