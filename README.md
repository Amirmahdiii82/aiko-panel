# پنل آیکو

اپلیکیشن مدیریتی یکپارچه آیکو کازمتیکس: **فروشگاه و حسابداری**، **قیمت رقبا** و **استودیو محتوا** در یک برنامه، با یک ورود، یک ظاهر (claymorphism، فارسی و راست‌به‌چپ، روشن/تیره، قابل نصب روی گوشی) و یک استقرار.

| بخش | از کجا آمد | چه می‌کند |
|---|---|---|
| خانه | جدید | خلاصه زنده همه بخش‌ها، میانبرها، فید یکپارچه رویدادها |
| فروشگاه و حسابداری (`erp`) | `../ERP` | انبار مرجع، فروش سریع از همه کانال‌ها، خرید، هزینه، حساب شرکا، همگام‌سازی ووکامرس |
| قیمت رقبا (`pricing`) | `../Price-checker` | مقایسه با دیجی‌کالا، ترب، باسلام و…، تأیید تطبیق‌ها، قیمت‌گذاری محصول جدید |
| استودیو محتوا (`media`) | `../media-studio-dev` (بازنویسی از Node به Python) | ساخت ویدیو و تصویر با OpenRouter، مقایسه تا ۳ مدل، کتابخانه مشترک تیم |
| تیم و دسترسی‌ها | جدید | هر نفر یک ورود؛ نقش جدا در هر بخش (مثلاً فروشنده در فروشگاه، فقط‌مشاهده در قیمت‌ها) |
| تنظیمات | جدید | اعلان بله/تلگرام برای همه بخش‌ها، وضعیت سیستم، پشتیبان‌ها |

معماری و دلایل انتخاب‌ها: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## تغییرات نسبت به برنامه‌های جدا

* **یک ورود و دسترسی نقش‌محور**: قیمت‌ها قبلاً فقط یک رمز مشترک (HTTP Basic) داشت؛ استودیو هیچ ورودی نداشت.
* **استودیو در سرور**: تاریخچه قبلاً فقط در مرورگر بود و با بستن صفحه، پیگیری ویدیو متوقف می‌شد. حالا سرور خودش کارها را دنبال می‌کند، ویدیو را دانلود و نگه می‌دارد (بعد از انقضا در OpenRouter هم می‌ماند)، کتابخانه بین همه مشترک است، سقف هزینه ماهانه دارد و آماده شدن ویدیو اعلان می‌دهد.
* **بروزرسانی زنده قیمت‌ها**: پیشرفت بروزرسانی بدون polling (SSE) نشان داده می‌شود و در پایان، خلاصه (محصولات در خطر، فرصت‌ها) در فید و اگر بخواهید در بله می‌آید.
* **یک باگ قدیمی برطرف شد**: در برنامه قیمت قبلی، اگر `CRAWL_TIMES` تنظیم شده بود، بروزرسانی زمان‌بندی‌شده در یک thread بدون event loop اجرا می‌شد و با خطای `no running event loop` شروع نمی‌شد (فقط دکمه دستی کار می‌کرد).
* **پشتیبان خودکار شبانه** از همه پایگاه‌داده‌ها و فایل‌ها، و عکس قبل از هر استقرار با بازگشت خودکار.

## اجرا روی کامپیوتر خودتان

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
cp .env.example .env                    # برای توسعه همین کافی است
.venv/bin/python -m app serve           # http://127.0.0.1:8020
```

ورود اول: `amir` یا `tina` با رمز `INITIAL_PASSWORD` (در `.env`). بعد از ورود از «حساب من» رمز را عوض کنید.

آوردن داده‌های فعلی (فقط یک بار، روی پوشه `data` خالی):

```bash
.venv/bin/python -m app import-legacy --erp ../ERP/data/aiko.db --pricing ../Price-checker/data/prices.db --uploads ../ERP/data/uploads
```

کاربران و رمزهای ERP همان می‌مانند (مدیرهای قبلی «مدیر کل» می‌شوند، فروشنده‌ها نقش فروشنده در فروشگاه را می‌گیرند). پایگاه‌داده‌های قدیمی فقط خوانده می‌شوند.

دستورهای دیگر:

```bash
python -m app migrate                       # به‌روزرسانی طرح همه پایگاه‌داده‌ها
python -m app set-password amir NEWPASS     # بازیابی رمز
python -m app backup [DIR]                  # پشتیبان همین الان
python -m app pricing crawl [site ...]      # بروزرسانی قیمت از خط فرمان
python -m app erp import-excel FILE.xlsx    # ورود اکسل قدیمی انبار
```

تست‌ها: `.venv/bin/python -m pytest -q`

## استقرار روی سرور (همان سرور ایران فعلی)

> ⚠️ سرور باید IP ایران داشته باشد (سایت آیکو، بلاران و بلا به IP خارج جواب نمی‌دهند و ترب IP دیتاسنتر خارجی را می‌بندد). برای OpenRouter که از ایران در دسترس نیست، در «تنظیمات استودیو» یک پروکسی خروجی بگذارید.

### بار اول

1. یک دامنه (پیش‌فرض در فایل‌ها `aiko.infinitcode.ir`) را به IP سرور وصل کنید.
2. کد را روی سرور ببرید (مثلاً با `scp` یک `git archive`) و در پوشه‌اش:
   ```bash
   sudo bash deploy/bootstrap-server.sh
   ```
   این اسکریپت کاربر سیستمی `aiko`، پوشه `/opt/aiko-panel`، محیط پایتون، `.env` (با تنظیمات خزنده از `.env` برنامه قیمت فعلی و یک رمز اولیه تصادفی)، **انتقال داده‌های price-checker موجود روی سرور** و سرویس‌های systemd را می‌سازد. برنامه قبلی تا وقتی خودتان سوئیچ نکنید دست نمی‌خورد.
   اگر داده ERP روی کامپیوتر شماست، قبل از اجرا آن را به سرور ببرید و مسیرش را بدهید: `sudo OLD_ERP=/root/aiko.db OLD_UPLOADS=/root/uploads bash deploy/bootstrap-server.sh`
3. در `/opt/aiko-panel/.env` مقدار `PUBLIC_URL` و `COOKIE_SECURE=1` را بگذارید و `systemctl restart aiko-panel`.
4. بلوک `deploy/Caddyfile` را به `/etc/caddy/Caddyfile` اضافه و `systemctl reload caddy`.
5. وقتی همه چیز درست بود، برنامه قیمت قبلی را خاموش و دامنه قدیمی را به پنل redirect کنید (در انتهای خروجی اسکریپت توضیح داده شده).

### استقرار خودکار (CI/CD)

مثل برنامه قیمت فعلی، ولی با تست قبل از ارسال و بازگشت داده:

* هر push به `main` که در پیام یکی از کامیت‌ها `#deploy` باشد (یا «Run workflow» در Actions) → تست‌ها اجرا می‌شوند → بسته با امضای HMAC به `https://<دامنه>/__deploy` فرستاده می‌شود (SSH از بیرون لازم نیست و سرور به GitHub نیازی ندارد).
* روی سرور `deploy/deploy.sh`: عکس از همه پایگاه‌داده‌ها ← جایگزینی کد ← نصب وابستگی‌ها ← مهاجرت ← ری‌استارت ← بررسی `/healthz` ← اگر مشکل بود، کد قبلی **و داده قبلی** برمی‌گردد.
* در GitHub: secret به نام `DEPLOY_SECRET` (مقدار داخل `/etc/aiko-panel/deploy.env` — اگر price-checker روی سرور بود همان قبلی کپی می‌شود) و variable به نام `DEPLOY_URL`.
* `.env` و `data/` هرگز توسط استقرار دست نمی‌خورند.

### با Docker (جایگزین)

```bash
cp .env.example .env && docker compose up -d --build     # 127.0.0.1:8020
```

## نگهداری

* **پشتیبان**: هر شب ۳:۱۵ در `data/backups/YYYY-MM-DD/` (یک فایل برای هر بخش + آرشیو رسیدها و فایل‌های استودیو)، ۳۰ روز نگه داشته می‌شود. از «تنظیمات ← سیستم و پشتیبان» هم می‌توانید همه پایگاه‌داده‌ها را دانلود کنید. هر چند وقت یک بار یک نسخه بیرون از سرور نگه دارید.
* **بازگردانی**: سرویس را متوقف کنید، فایل `*.db` مربوط را از پوشه پشتیبان جای فایل `data/` بگذارید (فایل‌های `-wal` و `-shm` همان نام را پاک کنید)، سرویس را روشن کنید.
* **لاگ‌ها**: `journalctl -u aiko-panel -f`

## ساختار کد

```
app/
  main.py               ساخت برنامه: core + ماژول‌های فعال، پوسته، CSP
  __main__.py           دستورهای خط فرمان
  core/                 هسته مشترک
    auth.py             ورود، نشست، نقش هر ماژول
    db.py               پایگاه‌داده هر ماژول + مهاجرت‌ها
    events.py           رویدادهای زنده (SSE) و هوک‌های بین ماژول
    activity.py         فید یکپارچه، زنگوله، ربات بله/تلگرام
    jobs.py             زمان‌بندی و کارهای پس‌زمینه
    backup.py           پشتیبان‌گیری
    legacy.py           انتقال یک‌باره از برنامه‌های قبلی
    router.py           API هسته (ورود، تیم، خانه، رویدادها، تنظیمات، فایل‌ها)
    web/                پوسته و کیت مشترک فرانت‌اند (clay.css، kit.js، صفحه‌های هسته)
  modules/
    erp/                فروشگاه و حسابداری (+ web/ صفحه‌ها)
    pricing/            قیمت رقبا (+ sources/ خزنده‌ها، web/)
    media/              استودیو محتوا (+ web/)
deploy/                 systemd، Caddy، دریافت‌کننده استقرار، اسکریپت‌ها
tests/                  تست‌ها (pytest)
```

آیکون‌ها از [Lucide](https://lucide.dev) (ISC)، فونت وزیرمتن، نمودارها با Chart.js.
